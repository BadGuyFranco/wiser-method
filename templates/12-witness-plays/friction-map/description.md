# Friction Map

**Chapter:** 12 (Witness Plays)
**Base template:** portrait
**Pages:** 2
**WISER phase:** Witness
**Position:** Architect (leads), Scout (validates findings)

## Purpose

Document where work breaks down, why it breaks, and how much it costs. Provides the structured evidence needed to move from observation to prioritized action.

## When to Use

Early in the Witness phase, after completing initial observation sessions. Pull this out when you have raw observations and need to organize them into a prioritized map of friction points.

## Content Sections

### Page 1

**Header metadata:**
- Process Name
- Date Range Observed
- Observer(s)
- Number of Sessions

**Instructions box (tip):**
Observe the work happening before filling this out. Document what you see, not what people tell you happens. Each friction point should come from direct observation or validated interview data.

**Friction Point Entries (repeating, 3 on page 1):**
Each entry is a bordered card containing:
- Name (short descriptive name)
- Location in Process (where this occurs)
- Description (what happens)
- Frequency (how often: daily / weekly / per transaction)
- Time Impact (minutes/hours lost per occurrence)
- Who is Affected (roles impacted)
- Current Workaround (how people cope today)
- Root Cause Hypothesis (why this exists)
- Evidence Source (who/what showed you this)
- Severity badge (High / Medium / Low)

### Page 2

**Summary Table:**
Columns: Friction Point | Frequency | Time Impact per Occurrence | Daily Total Impact | Severity
5-8 writable rows.

**Severity Rating Criteria (info box, note style):**
- High: >30 minutes/day total impact
- Medium: 10-30 minutes/day total impact
- Low: <10 minutes/day total impact

**Patterns Observed:**
3-4 blank lines for noting patterns across friction points.

**Recommended Priority:**
Numbered list with 3 write-in entries for prioritized friction points.

**Pitfalls warning box:**
Common mistakes: documenting symptoms instead of causes; relying only on manager descriptions; not quantifying time impact; confusing inconvenience with actual friction.

## Design Notes

- Friction Point entries should be compact enough to fit 3 on the first page
- The summary table on page 2 serves as the "at a glance" view
- Severity badges use the color-coded badge classes (high=red, medium=orange, low=teal)
