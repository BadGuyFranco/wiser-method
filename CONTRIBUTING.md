# Contributing to the WISER Method

We welcome contributions that improve the WISER Method and its practitioner templates.

## What We Accept

- **Template improvements**: Better description specs, new template views, clearer field descriptions
- **New templates**: Templates that support existing WISER canons and plays
- **Corrections**: Fixes to errors, typos, or broken links
- **Translations**: Translations of the method or templates into other languages (must include full attribution)

## What We Don't Accept

- Changes to the core methodology (`method/WISER Method.md`) without prior discussion
- Content that requires proprietary tools or platforms to use
- Marketing or promotional content

## How to Contribute

1. **Open an issue first.** Describe what you want to change and why. For template improvements, reference the relevant canon and chapter.
2. **Fork the repository** and create a branch for your changes.
3. **Follow the existing structure.** Templates use the description spec format documented in `templates/AGENTS.md`. Match the style and level of detail.
4. **Submit a pull request.** Reference the issue. Describe what changed and how to verify it.

## Developer Certificate of Origin

By contributing, you certify that:

- You wrote the contribution, or have the right to submit it under the CC BY-SA 4.0 license.
- You understand your contribution will be licensed under CC BY-SA 4.0.
- You have the authority to make this certification.

Include a `Signed-off-by` line in your commit messages:

```
Signed-off-by: Your Name <your.email@example.com>
```

This can be done automatically with `git commit -s`.

## Style Guidelines

- Use clear, direct language
- Keep templates format-neutral (they should work in any tool)
- Include example entries in description specs
- Test HTML templates render correctly before submitting

## Questions?

Open an issue with the `question` label.
